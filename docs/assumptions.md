# Assumptions

1. SQLite is the default demo database so `python run_demo.py` stays zero-config.
2. The current API query layer is SQLite-compatible raw SQL. SQLAlchemy 2.x metadata/session support is retained as the migration foundation, but the runtime is not yet a full ORM implementation.
3. Semantic scoring uses `all-MiniLM-L6-v2` only when the optional dependency/model is available. Otherwise the API labels the method as a TF-IDF word/character semantic fallback.
4. Synthetic ML data is always labelled `synthetic=true` and is not evidence of production placement performance.
5. Graduation year 2026 or later is considered aligned with the demo cohort.
6. Recruiter identity is released only for Shortlisted, Interview or Selected applications. Blind mode is enforced server-side.
7. Seeded application scores are generated by the live scoring service; demo status values are seeded separately to create a realistic workflow.
8. A recruiter-created job is pending until admin approval, even when the recruiter company is already approved.
9. The demo uses an in-memory rate limiter because it has no shared infrastructure requirement.
